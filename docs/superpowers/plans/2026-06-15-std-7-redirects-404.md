# ITG-972 · STD-7 — 301-redirects-editor + redigerbar 404

EPIC: ITG-965 (CMS-STD). Worktree-isoleret. DoD: ITG-489.

## Mål
Kunden/ITGo styrer 301/302-redirects (kritisk ved retrofit hvor URL'er skifter) + en pæn,
redigerbar 404 med navigation.

## Designbeslutninger
- **Redirects i site-settings**: `redirects`-liste `{ from, to, permanent }` (permanent=true→301,
  ellers 302). Redigeres i Studio.
- **`_redirects`-emission (CF Pages)**: lille Astro-integration (`src/integrations/emit-redirects.ts`)
  på `astro:build:done` der læser `site.yml` (via `src/lib/redirects.ts`) og skriver `dist/_redirects`
  (`<from> <to> <status>`). Statisk build → ingen SSR nødvendig. Tom liste → ingen fil.
  (Astro-routing ignorerer `_`-prefiks i src/pages, så en endpoint-fil kan ikke hedde `_redirects`
  → integration-hook er den rigtige vej.)
- **Validering**: `from` bør starte med `/` (advarsel, ikke crash); tomme felter springes over.
- **Redigerbar 404**: `src/pages/404.astro` renderer en content-side med slug `404` hvis kunden har
  oprettet en (editable); ellers en pæn default ("Siden blev ikke fundet") med **navigation-forslag
  fra menuen** (STD-3) + link til forsiden. CF Pages serverer `dist/404.html` ved ukendt URL.
- **Slug-ændring → auto-redirect**: kobler til STD-2 (sidestyring, ikke bygget) → **pass 2**.

## Filer
1. `src/content.config.ts` — `redirects` i `siteSettingsSchema`.
2. `src/lib/settings.ts` — `redirects: []` i DEFAULTS.
3. `studio.config.yml` — `redirects`-liste-felt.
4. `src/lib/redirects.ts` — `readRedirects()` + `toRedirectsFile()` (ren, fs+yaml).
5. `src/integrations/emit-redirects.ts` — build:done-hook → `dist/_redirects`.
6. `astro.config.mjs` — registrér integration.
7. `src/pages/404.astro` — redigerbar/​default 404 + menu-forslag.
8. `docs/site-settings.md` — redirects/404-afsnit.
